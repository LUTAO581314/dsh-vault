# DSH 预设创建与维护规则

更新：2026-10-21。本文件是本机维护约定，不代表 DSH 官方接口。

## 1. 架构与范围

启动加载 bundle 补丁，再应用 profile 补丁。普通插件行可在 Host 注册服务、工具和提示词；preset 的 `config.plugins` 在独立作用域组成一个代际，Agent 绑定该代际。工具可见集合可能包含继承的全局工具，所以插件条目数不等于工具数，缩短 persona 也不等于已隔离工具。

新会话选 preset 后：公共必需上下文 + 该 preset 的身份/工作规则 + 实际可见工具 schema + 会话历史进入请求。工具 schema 通常是独立 API 字段，不等同于系统消息文本，但同样占请求预算。413 可能来自本地预检、提供方窗口或网关体积限制，应凭实际错误与请求记录区分。

现有会话和子代理可能保留旧代际；重启按 ID 恢复当前定义。不要为美化命名直接修改已有 config.id，也不要禁用旧 ID 后宣称历史会话自动回退。

## 2. 创建规则

- 一档一职责；声明 name、description、order、稳定的 config.id。
- 新 ID 用 kebab-case；既有 rea-re2 等 ID 保留兼容，迁移另做。
- persona 建议500–2000字符，超过是检查信号而非系统限制；角色卡允许有理由例外。
- persona 只放身份、任务选择、关键约束、输出契约。脚本、长SOP、排障参数放 skill 或显式 read 的参考文件。
- 历史环境记录带日期；调用前复核，不当作永久事实。
- 只声明真实可见的工具；全局来源也应记录，最终以运行时工具目录为准。
- 工具列表和系统提示词分别预算；不得以修改 contextWindow 元数据替代瘦身。
- 采用完整的 plugins 数组覆盖时保留原组的 isolate/disabled/条件表达式，并记录与内置版本的差异。
- 避免未注册模板变量，工作目录从运行时上下文获取。
- 自检限于当前任务，不在每次开场自动跑生图、付费请求、联网探测。
- 干活档按需组合文件/shell/web/todo；聊天档不强制携带写入、shell或委派。控制面UI和数据服务是否适合移入preset需逐插件验证，勿一键搬迁所有插件。

## 3. 提示词文件与创建入口

原生 persona prefix/suffix 在 preset 内生效。另有本机对 dsh-purge 的本地改动：优先读取 `$DSH_HOME/prompt-inject/<id>.md`，再找 `prompt-inject.<id>.md`，否则沿用原全局注入。空文件也会回落，不能用空文件表示禁用。

这条额外路径仅做过语法检查；尚待真实组装验证是否有其他注入通道叠加旧全文。插件更新可能覆盖本地代码，备份不等于持久功能。

新增预设时须同时记录：①声明行/插件来源；②persona或专属注入文件；③技能/参考文件；④全局工具依赖；⑤静态与运行时验收。不要重复复制全局长稿作为每档默认配置。

## 4. 维护流程

1. 先备份当前 profile 与相关参考文件。
2. 从当前内置或第三方bundle读定义，按真实加载顺序应用覆盖；不能只扫描profile便称为全部预设。
3. 保留旧ID与用户选择，避免改默认模型/窗口和身份内容等无关设置。
4. 更新描述、persona与专属能力；长内容先归档再缩短，保证可读取。
5. 在当前配置目录执行 `node check-presets.cjs`：检查YAML含 !!js、重复声明、persona、模板变量、直接MCP与注入文件大小。
6. 重启或按实际支持方式刷新后，新开至少两种preset核对最终系统消息和工具目录。比较实际schema字节/token与首轮请求，不只比较文件大小。
7. 用较小窗口模型首轮与第二轮各测一次；检查并发会话的提示词和工具无串用。付费/生成类工具仅在用户明确要求时测。
